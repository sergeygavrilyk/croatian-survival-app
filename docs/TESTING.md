# Тестування

Відповідає Definition of Done (§94) і Release Gate (§96). Три рівні: unit, інтеграційні (БД) і E2E.

## 3. E2E — ручний чекліст (поки без автоматизації)

Автоматичний E2E (Playwright) потребує тестового акаунта і запуску застосунку в CI — це окреме рішення (PROPOSE). Поки що — чекліст, який проходить власник, а Claude звіряє результат у базі.

### VS-002 — урок

1. `npm run dev`, увійти, відкрити `/lesson/c0000000-0000-0000-0000-000000000001`.
2. «Почати урок» → слова → діалоги → вправи.
3. На одній вправі відповісти неправильно → «Ця вправа повториться наприкінці»; наприкінці відповісти правильно.
4. Після останньої вправи — «Урок пройдено!» і «Прогрес збережено».

Очікувано в БД: `lesson_progress` = completed; слова уроку в `user_progress` (ті, що вже були, не змінились); події `lesson_started`, `exercise_completed` (у повтореної — attempt = 2), `lesson_completed`.

### VS-001 — тренажер

**Режим «👀 Картки»**
1. Відкрити `/trainer`, обрати рівень A1.
2. Тапнути картку: видно переклад і (якщо є) приклад речення; 🔊 озвучує приклад.
3. Посвайпати всі картки (частину «Знаю», частину «Не знаю»). Якщо повторень мало, сесія доповнюється новими словами до 10.

Очікувано: для кожної картки — рядок у `srs_reviews` з `response_time_ms`; «Знаю» → наступний повтор завтра або пізніше, «Не знаю» → сьогодні; події `review_started` / `review_completed` з `source` = `review` або `new`.

**Режим «✍️ Написати»** (лише слова, які вже вчаться)
1. Перемкнути на «✍️ Написати».
2. Ввести одне слово правильно, одне — без діакритики (напр. `kuca`), одне неправильно, на одне натиснути «Не знаю». Кнопки č ć đ š ž вставляють літеру в поле.
3. Після кожної відповіді: вердикт, правильне слово, озвучення, приклад; Enter або «Далі ➔» — наступне слово.

Очікувано: `exercise_completed` з `exercise_type` = `type_word`, `verdict` = exact / diacritics / wrong; правильні (зокрема без діакритики) → повтор пізніше, неправильні → сьогодні; `review_completed` з `source` = `write`.

### Перевірка подій у SQL Editor

```sql
select occurred_at, event_name, level, success, duration_ms, properties
from public.analytics_events
order by occurred_at desc
limit 20;
```

### Дизайн-система (UI-001 / UI-002)

1. Шрифт — не Arial: заголовки (Plus Jakarta Sans) помітно відрізняються від тексту (Inter); літери č ć đ š ž виглядають тим самим шрифтом.
2. Фон сторінок світло-сірий (slate-50). У телефоні з темною темою застосунок лишається світлим, текст читається.
3. Внизу одна панель: **Сьогодні · Уроки · Практика · Ситуації · Профіль**. Активна вкладка синя й жирна. Переходи працюють, на `/dictionary` активна «Практика».
4. На `/trainer` і `/dictionary` угорі «Практика» і вкладки «Тренажер · Словник».
5. `/situations` — екран «Розділ готується» з кнопкою «До уроків».
6. В уроці (`/lesson/…`), на `/login` і `/admin` нижньої панелі немає.
7. Останні елементи сторінок не ховаються під панеллю (прокрутити до кінця головної, уроків, словника, профілю).
8. Телефон: сторінку можна збільшити двома пальцями; на iPhone панель не налазить на системну смугу внизу.
9. Клавіатура: Tab показує синю рамку фокусу на кнопках і вкладках.

### Ситуації, Прогрес, Онбординг (2026-10-12)

**Онбординг** (після M7 головна сама перекине на `/onboarding`):
1. Мета: можна обрати кілька; «Далі» неактивна, доки нічого не обрано.
2. Щоденна ціль → самооцінка. «Починаю з нуля» → одразу «Почати навчання» → головна.
3. Інша самооцінка → «Короткий тест рівня». До публікації тесту видно повідомлення «Тест ще проходить перевірку» і кнопку «Почати з рівня …».
4. Після публікації:
   - пройти тест: варіанти з хорватським текстом, «Не знаю»;
   - якщо на рівні 3 «Не знаю» — тест завершується раніше;
   - результат з позначкою «оцінка застосунку», смуги за рівнями, вибір рівня старту, «Розбір відповідей».
5. У БД:
   - `profiles` — `onboarding_completed = true`, цілі, рівень;
   - `assessment_attempts` — один рядок;
   - `analytics_events` — `onboarding_started` / `completed`, `placement_started` / `completed`.

**Ситуації:**
1. `/situations`: картки з підписами на кшталт «A1 · 15 фраз · 1 діалог».
2. Ситуація «Здоров'я і аптека»:
   - вкладки «Фрази · 15» / «Діалоги · 1»;
   - 🔊 біля кожної фрази;
   - «←» повертає до списку.
3. «Перевір себе»: переклад → «Показати» → фраза + 🔊 → «Знав / Ще ні» → у кінці «X з Y» і «Ще раз». У `analytics_events` — `exercise_completed` з `phrase_recall`.
4. «Діалоги»: бульбашки двох мовців, «Сховати переклад».
5. `/situations/nonexistent` → сторінка 404.

**Прогрес** (вкладка «Профіль»):
1. Плитки: уроки, слова, «Повторити зараз» (кнопка веде в тренажер), засвоєно надовго.
2. «Повторення за 7 днів»: стовпці, сьогоднішній день виділено, підпис над піком і сьогодні; наведення показує значення.
3. «Слова за рівнями».
4. «Рівень і цілі»: рівень старту, результат тесту, щоденна ціль, мета; «Змінити цілі або пройти тест рівня» → `/onboarding` (з «←» назад у профіль).
5. «Змінити пароль» і «Вийти» працюють.

### Говоріння (VS-003)

Мікрофон працює лише на `http://localhost:3000` або через `https`. З телефона за адресою на кшталт `http://192.168…` браузер мікрофон не дасть. Найкраще — Chrome або Edge на комп'ютері чи Android, Safari на iPhone. У Firefox розпізнавання немає: має з'явитися пояснення і кнопка «Перевір себе без мікрофона».

1. «Ситуації» → «Здоров'я і аптека» → «Фрази» → **Говорити** → видно два режими і примітку про приватність.
2. «Повторити за диктором»:
   - браузер питає дозвіл на мікрофон → дозволити;
   - натиснути мікрофон, сказати фразу → кнопка червона, видно проміжний текст;
   - після паузи — відгук.
3. Сказати фразу правильно → «Чудово! Вас зрозуміють». Пропустити останнє слово → «Зрозуміло» або «Майже», слово на бурштиновому тлі й у «Попрацюйте над словами» з 🔊.
4. «Ще раз» → нова спроба тієї ж фрази; «Далі» → наступна фраза; у кінці — «X з Y».
5. «Сказати самому»: видно лише переклад, хорватська фраза з'являється після відповіді.
6. Заборонити мікрофон у браузері → зрозуміле пояснення, як дозволити.
7. У БД:
   - `speaking_sessions` — рядок з `ended_at` після завершення;
   - `speaking_attempts` — спроби з `transcript` і `verdict`, без аудіо;
   - `analytics_events` — `speaking_started` / `speaking_completed`.

### Рольова гра з AI (VS-004)

Потрібен ключ `GEMINI_API_KEY` у `.env.local` (той самий, що для перекладу на головній). Модель можна змінити змінною `GEMINI_MODEL`.

1. «Ситуації» → «Кафе і ресторан» → індиго-картка **Рольова гра з AI** → вступ: співрозмовник *konobar*, завдання, рівень → «Почати розмову».
