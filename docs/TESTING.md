## 2. Інтеграційні тести БД — `supabase/tests/*.test.sql`

Перевіряють міграції, обмеження й RLS від імені двох тестових користувачів і гостя.

- **Безпечно для робочої бази:** скрипт виконується в одній транзакції і завершується `ROLLBACK`.
- Запуск: у CI — на тестовій базі (`curdb.sh` + `sqltests.sh`) на кожному PR; у робочій базі — тести, змінені в PR, запускає workflow «Apply SQL (production)» після мержу й Approve власника (`docs/SQL_AUTOMATION.md`). Старі чеклісти зі «SQL Editor» (до 2026-11-07) — в архіві `docs/archive/TESTING_manual_checklists_2026-10_11.md`.
- Успіх: останній рядок — `ALL TESTS PASSED`. Збій зупиняє скрипт з повідомленням `FAIL: …`.

Рішення власника 2026-10-21: E2E з тестовим акаунтом — на комп'ютері власника. **З 2026-11-14** (рішення власника: секрети додано, «Додав») — ще й у CI на кожному PR: робота `e2e-user` (§4) з репозиторних секретів GitHub.

| Файл | Що перевіряє |
|---|---|
| `e2e/smoke.spec.ts` (проєкт `smoke`, і в CI) | Вхід: форма українською, `lang="uk"`, перемикач «Реєстрація» з підказкою про довжину пароля; без входу `/lessons`, `/lessons?level=A1`, `/lesson/…`, `/lessons/grammar?level=A1`, `/lessons/grammar/review?level=A0` → вхід; `/reading/<хибна адреса>` → «Текст не знайдено» → «До текстів»; `/api/tts` без входу → 401 (з 2026-11-11); PWA зібрано (`/manifest.json` з іконками, `/sw.js`) |
| `e2e/auth.setup.ts` (проєкт `setup`) | Вхід тестовим акаунтом, сесія → `e2e/.auth/user.json` (у git не потрапляє); зрозуміла помилка, якщо пароль хибний або акаунт не пройшов онбординг |
| `e2e/user.spec.ts` (проєкт `user`) | «Уроки»: A0 за замовчуванням, перший модуль розгорнуто, A1 → `/lessons?level=A1` (`aria-current`), «Назад» → A0; тестовий урок від «Почати урок» через усі етапи й 17 вправ («не знаю» / «не можу говорити» / «Пропустити» письмо й переказ / перший варіант — неправильна вправа повторюється раз) до «Урок пройдено!» і «Прогрес збережено» без помилки; «Урок не знайдено»; **граматика рівня:** «Уроки» A1 → «Граматика рівня A1» → пошук *akuzativ* → тема «Знахідний відмінок» → «Потренувати тему» (вправа 1) → закрити; «Підсумок граматики A0»: «Треба повторити» → «Далі: вправи»; **словник:** пошук *pomidor* → картка слова («регіонально») → «Додати в повторення» → «Додано…» (або «вже вчите»), Escape закриває, у списку — «Вчу»; читання: список → текст; **рівні з бази:** «Перевірки рівня» показують A0 · A1 · A2 і фінал A2, «Уроки» A2 — «Перевірки рівня A2», перевірка модуля й фінал; **ситуації:** фільтр рівня діалогів і фраз («Перевір себе» — лише вибраний рівень); **профіль:** «Показувати контент 18+» — вимкнено, «Скасувати» підтвердження лишає вимкненим, «Так, мені 18+» вмикає, потім знову вимикаємо (до запуску M26 — пропуск); **оновлення застосунку:** сторінку уроку в кеші «від старої версії» оновлено самою, без мережі урок відкривається; **офлайн наперед:** відкрили урок 1 — наступні уроки модуля й тексти в кеші, «Сьогодні» — ситуації; без мережі ще не відкритий урок, текст і фрази ситуації відкриваються, діалоги — «з інтернетом»; **словник без інтернету:** пошук слова з відкритого уроку, повернення мережі — знову весь словник; **«Сьогодні» на iPhone:** підказка «Додати на початковий екран» з кроками, «Не зараз» ховає й після оновлення; **офлайн (§76):** урок і текст після відкриття лежать у кеші PWA і відкриваються з вимкненою мережею — кожен у новій вкладці; подія «мережа з'явилась» (`online`) не перезавантажує сторінку уроку; перехід «Читання» → текст усередині застосунку; якщо тест падає — журнал переходів (хто і куди перезавантажив сторінку, зі стеком) у лозі (лише у збірці); **офлайн без втрат (2026-11-16):** урок, коли виклики сервера обриваються, — «Прогрес збережемо, щойно з’явиться інтернет», у черзі `lesson_completed`, на «Уроках» — «… чекають на інтернет»; зв'язок повернувся (`online`) — черга порожня, значка немає; текст з вимкненою мережею — «Результат збережемо…», мережа є — черга порожня; **тренажер без мережі (етап 2):** онлайн збережено копію колоди, без мережі «Написати» — «Без інтернету: картки з телефона», «Не знаю» → `srs_rating` у черзі без червоної помилки, мережа є — черга порожня |

**Перший раз (на комп'ютері власника):**

1. `npm install -D @playwright/test` і `npx playwright install chromium`.
2. Тестовий акаунт: на `http://localhost:3000/login` → «Реєстрація» з окремою поштою (не основною), підтвердити лист, **пройти онбординг до кінця**.
3. У `.env.local` дописати (у git не потрапляє):
   ```
   E2E_EMAIL=пошта тестового акаунта
   E2E_PASSWORD=його пароль
   ```

**Запуск:** `npm run e2e` — збирає застосунок (`npm run build`), запускає його на `http://localhost:3100` (не заважає `npm run dev` на :3000) і проходить усі сценарії (~3–5 хв). Лише без входу: `npm run e2e:smoke`. Звіт зі скриншотами й записом кроків упалого тесту: `npx playwright show-report`. Проти вже запущеного сервера: `E2E_BASE_URL=http://localhost:3000 npm run e2e` (офлайн-тест тоді пропускається — у dev PWA вимкнено).

Тести пишуть у робочу базу лише дані **тестового акаунта**: прогрес уроку, слова в повторенні, події аналітики (`lesson_started`, `exercise_completed`, `lesson_completed`). Звіряючи аналітику, тестовий акаунт варто не враховувати.

**Ручні перевірки** — те, чого автоматичні тести не покривають (звук, мікрофон, вигляд, телефон): з 2026-11-14 кроки «як перевірити» для кожної задачі — **в описі її PR** і у звіті Claude власнику. Старі ручні чеклісти (2026-10-12 … 2026-11-13) — в архіві `docs/archive/TESTING_manual_checklists_2026-10_11.md` (заморожено). Після запуску SQL Claude звіряє результат у базі (лише читання).

## 4. CI — GitHub Actions (з 2026-10-21)

`.github/workflows/ci.yml` запускається після кожного push і pull request (і вручну: GitHub → Actions → CI → Run workflow). Збірка й smoke — з підставними адресами Supabase, SQL-тести — на чистій Postgres у GitHub; E2E з входом (`e2e-user`) — з репозиторних секретів.

| Робота | Кроки |
|---|---|
| `app` | `npm ci` → `npm run lint` → `npm test` → `npm run build` → `npm run typecheck` (після збірки: потрібні `next-env.d.ts` і `.next/types`) → `npm run e2e:smoke`; якщо впало — звіт Playwright у «Artifacts» запуску |
| `sql` | (лише PR) `scripts/dev/check_frozen_sql.sh HEAD^1 HEAD` — уже змерджені SQL не змінено → PostgreSQL 16 → `sudo bash scripts/dev/curdb.sh` (міграції й пакети контенту) → `bash scripts/dev/sqltests.sh` (усі `supabase/tests/*.test.sql`) |
| `e2e-user` (з 2026-11-14) | Паралельно з `app` (з 2026-11-16, рішення власника: CI ~2,5 хв замість ~4,5; запускається, навіть якщо lint чи unit-тести впали), лише для PR, ручного запуску й `main` (push у гілку з PR не дублює). Перевіряє секрети → `npm ci` → `npm run build` зі справжньою адресою Supabase → `npx playwright test --project=setup --project=user`. Секрети — **Repository secrets** (Settings → Secrets and variables → Actions): `E2E_EMAIL`, `E2E_PASSWORD`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`; **не** в середовищі `production` (там лише `SUPABASE_DB_URL` для «Apply SQL» з Approve). Немає секретів (PR із форку чи ще не додано) — кроки пропущено, у підсумку — примітка. Запуски по черзі (`concurrency: e2e-test-account`): один акаунт. Пише в робочу базу лише прогрес і події тестового акаунта. Звіт Playwright **не вивантажується** (запис кроків містить пароль, репозиторій публічний; GitHub ховає значення секретів у лозі) — що впало, видно в лозі кроку, повний звіт — `npm run e2e` локально |

Результат — ✅ / ❌ біля коміту на GitHub; лист про ❌ — за налаштуваннями сповіщень GitHub. Новий пакет контенту — рядок у `curdb.sh` (як і раніше), інакше SQL-тест пакета впаде в CI.

**Оновлення залежностей — Dependabot (з 2026-11-11, рішення власника «щомісячна перевірка на вразливості та пошук оновлень»).** `.github/dependabot.yml`: раз на місяць GitHub сам відкриває PR з новими версіями — `next` + `eslint-config-next` одним PR (група `nextjs`), решта мінорних і патч-версій npm — другим, GitHub Actions — третім. Мажорних версій автоматично не пропонує (готує Claude окремим PR). На кожному такому PR іде CI; мерж — лише власник. Додатково раз на місяць заплановане завдання Claude перевіряє вразливості всіх проєктів (залежності, Security Advisor Supabase, новини про вразливості) і надсилає звіт; сповіщення GitHub про вразливості (Settings → Advanced Security → Dependabot alerts) вмикає власник.
